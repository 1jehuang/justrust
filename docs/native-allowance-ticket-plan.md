# Native frontend allowance tickets: executable design and acceptance gates

Status: design frozen, 2026-10-14. A separate experimental `TicketedProxy` A/P implementation is underway under another owner's assignment. Legacy Proxy remains the compiler default. This prototype names the selected request's grant source, with H/holder capabilities, provider/Registry redesign and query linkage deferred. No runtime changes, builds, tests, or commits performed by this document author. This document is the only owned file. Based on the panda panel `panel-3c28529a-cc9f-4d9f-8c1b-a2ee5372de01.md` and direct inspection of the current owned rustc source. Frozen schema4 point mapping is not changed. Internal redesign is allowed; supported compilation, diagnostics, manifests, jobserver behavior and deadlock recovery remain the external contract.

## 1. Actual boundary and missing authority

`compiler/rustc_data_structures/src/jobserver.rs` has process-global Client initialization (7-70), Proxy counts `used: u16, pending: u16` (73-85), initial `used=1` (104-110), helper delivery (114-133), acquire (141-156), and release (160-176). Pending acquire issues a helper request and waits once. Neither notify_one nor return checks a recipient predicate. Release decrements pending without identifying the recipient; helper success does the same while incrementing used. Helper errors do nothing. Surplus token destruction and raw release happen outside the Proxy lock. There is no Proxy Drop implementation in this file. Do not assume helper cancellation, callback drainage or destruction order without inspecting the pinned jobserver crate implementation before implementation.

Frontend construction is `rustc_interface/src/util.rs:252-259`. Registry callbacks are zero-argument unit-returning functions (`rustc_thread_pool/src/registry.rs:417-425`), used by startup, termination, external installation, shutdown, query blocking and scheduler sleep. `mark_blocked_and_wait:639-648` releases before waiting and reacquires afterward. Query `execution.rs:202-235` currently holds the latch lock during release but drops it before reacquire. Scheduler sleep holds its sleep-state lock during release and drops it before acquire (`sleep/mod.rs:245-254`). These orders are constraints, not opportunities to introduce recorder locks.

A protected ticket predicate is a behavioral change, including eliminating the current unconditional return on a spurious condvar wake. It cannot be advertised as tracing-only neutrality. Selection below is explicit implementation policy, not reconstructed FIFO timestamp causality. No edge to an individual Cargo/sibling/backend token owner is available.

## 2. Admission state independent of capture

### Recommended first prototype: exact grant decision, opaque holder

Coordinator refinement (hare, 2026-10-14): implement the bounded request/grant experiment BEFORE capability-bearing callback redesign. Keep the existing `acquire_thread() -> ()` and `release_thread() -> ()` interfaces. A release invocation gets its own operation identity at the actual protected Proxy transition and may grant one explicitly selected request. A helper callback gets a supply identity and may grant one explicitly selected request. The request checks its protected Granted predicate and acknowledges that grant before returning. This authorizes `release_operation -> grant -> request_ack/return` or `external_supply -> grant -> request_ack/return`. It does NOT authorize `held_lease -> release_operation`, releasing-thread ownership, or physical-token lineage.

For this prototype use A and P below, but omit H and allowance capabilities entirely. A counts all admitted units, including granted-but-unacknowledged requests, as the current used count does. Release assumes the existing balanced caller contract, decrements A only when no Pending recipient exists, and otherwise leaves A unchanged. Donor source is `LocalTransfer{release_operation}`, never `predecessor_allowance`. Immediate source is retained implicit entitlement with opaque prior holder. Preserve all existing callback sites and aggregate accounting without attributing their owner by OS thread, task TLS or timestamps. Capture receipt declares `authority=exact_grant_decision`, `lease_holder=unknown`, aggregate conservation scope, late-attachment opacity and external-jobserver exclusions. This smaller native change does not require adopting bootstrap ownership or changing Registry/provider interfaces.

Queue selection and per-request targeted Condvar are native admission policy regardless of capture enablement. Telemetry release/supply IDs are optional facts qualifying protected transitions, never admission inputs. Capture exhaustion suppresses authority, not grants. Native request identity is the live stable slot and predicate; do not require a capture allocator to admit work. Measure targeted-CV allocation/lock cost and, separately, a shared notify_all/predicate alternative's fanout cost. A shared notify_one alone is invalid for targeted grants because it can wake a different Pending request while the selected recipient remains asleep.

### Frozen bounded implementation assignment

Current prototype mode clarification: `TicketedProxy::new_with_event_capacity(0)` disables event-buffer rows only. Independent inventory counters and optional identity allocation still execute under State in this mode. This is event-buffer-off, not zero-telemetry capture-off, and its comparison measures row-buffer cost only. The existing compiler's native-query capture-off/default path still uses legacy Proxy and is unaffected. No default promotion is authorized. The zero-observer/ID/TLS/buffer disabled-path requirements elsewhere in this plan describe a future fully integrated resource recorder, not an implemented property of this prototype.

Dependency baseline correction: the jobserver dependency 0.1.35 baseline is superseded because it mismatched the candidate's pinned dependency. The matched 0.1.34 baseline is pending. Do not use the superseded baseline for cost comparisons or claim matched measurement completion. This is coordination status, not a build or test performed by this document author.

Keep legacy `Proxy::new()` unchanged as the default. Add an explicitly selected experimental `new_ticketed` path and a private real-Client constructor, with mode fixed at Proxy construction. No default promotion from this design. Ticket mode executes identical native state/predicate logic with recording disabled or enabled. Start with actual Client/Proxy tests before frontend wiring; keep observer/receipt implementation a separate assignment. This is a source-owned native experiment, not a permanent interception shim.

Ticket requests use an `Arc<RequestSlot>` allocated before taking the Proxy mutex. Proxy Pending queue owns an Arc while queued; acquire owns another until acknowledgment. The slot contains its targeted Condvar and a small state cell accessed ONLY while the owning Proxy mutex is held. A slot is not reused for another acquire; Arc lifetime supplies native identity without address-based cross-run attribution or a wrapping native ID allocator. Move, do not clone, selected grant state into acknowledgment; retire the queue Arc on selection. Keep a separate immutable Proxy association to reject cross-Proxy slot misuse. Queue insertion may allocate, so use a prelinked node in the already allocated slot and an intrusive queue, or reserve all queue storage before entering the lock. Do not hide VecDeque growth under the lock.

Use `usize` aggregate A and Pending counts, not u16. Every increment/decrement uses checked arithmetic with invariant failure explicit, never wrap/saturate. Actual outstanding requests require distinct live allocations and are bounded by addressable process memory, so a usize counter must not overflow in a valid state. Still exercise injected small counter ceilings in tests and reject impossible mutation before consuming an external token or changing any request predicate. An invariant failure is an internal scheduler bug, not recorder overflow and not grounds to fabricate admission. The test constructor exposes validation of this path; it does not make arbitrary small caps production admission limits. Preserve A=0 implicit retention, A>0 helper acceptance, local transfer leaving A unchanged, and surplus token destruction after unlock.

Prototype source slice is jobserver.rs plus its real-Client tests. Subsequent explicit experimental frontend selection can reuse the existing unit callbacks and test real Registry integration. Full H/capability ownership, callback ABI redesign and startup adoption are deferred, not prerequisites. Measurement includes any Arc allocation/refcount and targeted-CV costs; correctness/observability value does not imply a speedup.

The capability design below is a separately gated expansion ONLY if named held-lease lineage is later required. Its owner-slot/provider requirements are not prerequisites for this exact-grant-decision prototype. Prototype tests use release-operation sources and aggregate assertions rather than lease-capability assertions. Independent capture inventories still cover every administrative callback and never imply holder ownership. The frozen compiler baseline supplied by main and sheep's `bench/allowance-tickets` ownership are implementation coordination inputs, not validation performed here.

Use a native `Allowance` capability and stable request slot, not an event row as authorization. All mutable admission fields are protected by one Proxy mutex:

* `A`: assigned capacity, counting acknowledged holders AND granted-but-unacknowledged requests. Initially one bootstrap caller capability. Zero means the permanent implicit entitlement is idle.
* `P`: intrusive collection of live request slots in Pending state. Each slot has private Condvar, stable lifetime, and `Pending | Granted{grant, allowance} | Acked | Cancelled` state. Waiter owns the slot through acknowledgment; grant stores no dangling stack pointer.
* `H`: acknowledged holder capabilities. The Registry/caller keeps an opaque allowance handle and must present it on release. Bootstrap ownership must explicitly be adopted by the creating external caller before pool startup. Workers get distinct holder slots; nested external installations preserve the appropriate caller slot rather than overwriting it.
* Each allowance is local logical capacity, NOT a physical jobserver byte. `A = |H| + |Granted|`. Pending excludes Granted. Logical retained external capacity is `max(A-1,0)`, with in-flight raw release attempts separately tracked. The implicit process entitlement is an accounting anchor, not an immutable physical identity attached to one worker.

Selection: remove a particular Pending slot under the mutex using a documented queue policy (initial experiment: registration-order queue). Record its actual identity. Other policies may be measured later. Queue ordering is a scheduler decision; timestamps do not establish queue order or receipt edges. Per-request Condvar avoids waking the wrong request. Shared notify_all with predicates is correct but is a separate measured alternative, not the default proposal.

Capabilities cannot be forged, duplicated, or released twice. Stable slot generations prevent reuse confusion. Use checked native counters with a representable bound tied to valid pool/caller concurrency; do not retain silent u16 overflow. Runtime capacity exhaustion cannot be handled by dropping a waiter or returning without a permit. Validate configured limits before startup, and define an explicit nonwrapping slot/generation exhaustion strategy before promotion (reuse only after retirement with unambiguous internal lifetime, or a larger representation). Recorder exhaustion is entirely separate and fails open.

## 3. Exact protected transitions

1. **Acquire:** create request slot outside Proxy lock. Under lock register request and increment attempted-operation inventory. If `A==0`, require P empty, allocate local grant from IdleImplicit, set Granted and A=1. Otherwise append Pending and issue the existing nonblocking helper request while protected, preserving registration/request ordering. Loop `while state == Pending { slot.cv.wait(&mut data) }`. No timeout, notification or spurious return authorizes acquisition.
2. **Grant:** only a mutex-held transition Pending -> Granted chooses recipient. Allocate grant identity, source, and allowance identity as part of that transition. Remove P exactly once. Notify that slot only after publishing Granted. Grant identity exists regardless of capture; telemetry IDs may qualify it separately without affecting authorization.
3. **Ack:** the requesting thread, under the same mutex, verifies its own Granted state, moves that allowance to its owner slot, changes state to Acked, and stores acknowledgment identity. A is unchanged. Return only after ack and unlock. A captured return endpoint is outside the lock and means the API actually returned, not merely that a grant was issued.
4. **Release with pending recipient:** validate/consume the caller's H capability, select Pending slot, and create new grant naming `source=LocalTransfer{release_id, predecessor_allowance}`. New recipient allowance succeeds the released allowance; A stays unchanged. Pending count decreases; H decreases and Granted increases. This is the named donor-release -> grant -> ack path even if another waiter wakes or returns first.
5. **Release without pending:** consume H and decrement A. If A==0, retain the permanent implicit entitlement; expose IdleImplicit with predecessor release. If A>0, mark an external raw-release obligation, unlock, call `release_raw`, and record actual success/error. Never claim a released physical token belonged to the retiring logical allowance: implicit capacity can migrate between logical holders. Failed raw release means externally retained surplus/unknown accounting, not a successful release and not reusable local capacity. Preserve the current ignored error result at the caller boundary.
6. **Helper success:** successful callback owns Acquired RAII value. Under lock, if P nonempty, select recipient, check A>0, consume token with drop_without_releasing, increment A, and publish Granted with `source=ExternalSupply{supply_id}`. No matching to a helper request's issuance position. If P empty, unlock then drop token; record surplus return intent and only claim outcomes the API exposes (Drop does not itself expose a successful raw-return receipt).
7. **Helper error:** record failed callback outcome without granting, decrementing P or waking a waiter as successful. Preserve current retry/error behavior; do not silently introduce terminal cancellation. Outstanding pending requests remain visible. Determine helper error continuation behavior from pinned implementation and exercise it before promotion.

Grant sources are IdleImplicit (initial or retained checkpoint), LocalTransfer (a named protected release), or ExternalSupply (a named callback acceptance). Every grant names one request; every ack names that grant; every named release consumes an acknowledged allowance. Actual return need not follow grant order. Query readiness is a different authority and has no grant power.

Unwind/cancellation policy: current blocking acquire is noncancellable. Do not add cancellation as a side effect of capture shutdown. If a future cancellable API is required, remove Pending under lock; reclaim a Granted-but-unacked allowance through the same transfer/retention/raw-release state machine, exactly once. Never discard it. Test-only abandoned requests must use this explicit operation, not dropped slot memory. Native allocation failure retains Rust's normal failure behavior, not invented successful admission.

## 4. Minimal implementation boundaries and shutdown

Phase A can ship safe observational endpoints without changing callbacks or admission. It cannot emit named pending grants, donor-recipient edges, or prove current wait returns authorized acquisition. Explicitly publish `grant_authority=unavailable`.

Phase B requires coordinated edits, not only jobserver.rs:

* jobserver.rs owns tickets, predicates, capability validation, supply transitions and independent counters. A private test constructor accepting a real Client avoids replacing the global OnceLock in parallel tests.
* rustc_thread_pool callback/builder/registry interfaces carry opaque allowance capability ownership, preferably a paired admission-provider interface whose acquire returns a handle and release consumes it. Registry worker and external-caller slots must cover ALL existing callbacks, including initial caller, nesting and termination. Preserve ordinary thread-pool users without a provider. Do not depend on active query/task TLS for ownership.
* rustc_interface util constructs and binds the provider to the actual pool and adopts bootstrap caller capacity. Shared-capture authority attaches explicitly through this owning path.
* query execution and mark_blocked_and_wait gain explicit optional wait context plumbing, not thread/time correlation. Recording adapter and new resource receipt live separately from frozen schema4.

Pool shutdown retains release -> wait stopped latches -> reacquire ordering. Do not mark Proxy closing while workers still need normal acquisition, and do not convert shutdown into synthetic grants. Seal capture after pool operations and callbacks are accounted for, or publish outstanding Pending/Granted/H and in-flight callbacks/releases as incomplete. Audit the existing Arc/helper callback ownership cycle and HelperThread Drop before choosing any native teardown change. A weak callback reference or explicit helper shutdown is a separate correctness change requiring callback-race and token-return tests. This slice must not opportunistically change lifecycle while claiming unchanged behavior.

Deadlock bookkeeping remains at existing Registry sites. Pending admission is not query blocked state. Grant reservation may leave no CPU-active holder if a selected waiter is descheduled; the old protocol allowed any awakened waiter to return. This is a real scheduling risk. Never steal a reserved grant without an explicit mutex-held revoke/reassign protocol. Validate cycle-break wake and pool termination under this reservation delay before choosing policy.

## 5. Independent capture inventory and late opacity

Resource namespace identifies one Proxy, never the global Client or all process capacity. Immutable reciprocal resource/pool/query capture IDs and Registry observer identity authorize joins. Backend schedulers, parent holders and sibling processes are excluded. IDs are bounded nonwrapping per namespace: acquire/release operation, helper issuance, callback supply, grant, allowance, ack, transition sequence. Native request slot identity is independent of telemetry allocation.

Maintain independent attempted/transition counters and allocator baselines/high waters, not inferred counts of rows written. Track registrations, immediate grants, transfer grants, external grants, acks, returns, releases, callback success/error/surplus, raw release attempts/outcomes, pending/granted/held and outstanding publication counts at attach/seal. Expected records derive from these transitions. Test omission of each record kind independently. A lock-linearized transition sequence is authoritative local order, not a wall-clock ordering claim.

Attach under Proxy mutex establishes a checkpoint and epoch boundary. Pre-existing holders and granted requests become explicit opaque origins; do not invent startup grants or earlier donor leases. A subsequently transferred allowance may name the new release and new recipient while its ancestry remains opaque. Existing Pending slots can receive new authoritative grants, but their missing acquire-start is declared. Seal does not cancel native work. Overflow, cap loss, write failure or nonquiescent seal prevents affected edge completeness; bounds do not constrain native work. Never wrap IDs or infer inventory from capped output. Resource completeness, task binding completeness and global jobserver coverage are distinct statuses.

Recording under lock: copy fixed-size transitions into a preallocated bounded ring with no allocation, IO, JSON, observer/task/receipt lock or blocking publication. Use one Proxy-owned sequence and independent loss counters. Drain outside ALL Proxy/query/sleep locks, not just outside Proxy: release is called while query/sleep locks are held. A dedicated capture drain or deferred outer endpoint flush satisfies this; release callbacks must not synchronously flush. Never lock Proxy while holding receipt state. Overflow changes recorder authority only. Grant callback needs immutable capture authority, not helper TLS.

Point sampling occurs only outside scheduler/query/Proxy locks; a query release point may be sampled before acquiring the query latch lock and qualified as a pre-call bracket, not exact release-transition time. Request/return samples similarly declare brackets and validated active task segments. Non-active, suspended, foreign-observer and clock-overflow states stay explicit. With capture off: no observer, telemetry ID/clock/TLS/queue/recorder work. Native ticket state and predicate logic still execute identically, so capture-off/on isolates recording, not the admission redesign.

## 6. Explicit query linkage

Pass a copyable optional context `{capture authority, wait_id, phase}` from diagnostic_wait to a context-aware blocking API. Associate the exact release operation and reacquire request with that wait in provider calls. Avoid making rustc_data_structures depend on rustc_session; use an opaque qualified context in the lower-level interface and adapt in session/query code. Existing context-free calls remain administrative/unbound. A query wait owns one release and one reacquire request in the normal path, with explicit unwind/outstanding outcome where execution terminates early.

Retain mark_blocked -> release -> wait -> drop query guard -> acquire -> resumed. Notify/cycle notification records prove readiness; condvar-return alone is not renamed readiness. Graph may contain query-notify -> observed resume and native donor-release -> grant -> ack, linked by wait_id/request, without inventing notification -> grant causality. Already-complete queries have no fabricated wait/release. Capture loss or late attachment leaves linkage unknown.

## 7. Executable native contention acceptance matrix

Implement tests in the real rustc_data_structures Proxy and real rustc_thread_pool integration test harness, using a private real Client and the actual frontend builder/provider wiring. Do not duplicate the state machine into a synthetic mock. Run compiler integration fixtures for actual query cycle/error behavior. Test hooks pause at documented boundaries via channels/barriers OUTSIDE production locks. A watchdog can fail a hung test, but sleeps/timeouts are not ordering or donor oracles. A hook under lock may emit a nonblocking phase signal only; it cannot wait for a controller needing that lock.

1. Hold the bootstrap entitlement and exhaust Client external tokens using real Acquired handles. Register W1/W2 with barriers confirming Pending under mutex. Release named holder R. Pause selected W1 before ack, spuriously notify W2. Assert W2 stays Pending and does not return; grant identifies W1 and R. Release an external handle to grant W2, allow W2 ack/return before W1. Assert reverse return order does not change named edges.
2. Race a local release and real helper success using separate phase gates. Test both protected orderings explicitly. Require exactly one grant per request, A conservation, no duplicate ack, and helper surplus after all Pending consumed. Reacquire returned external capacity with the same Client to verify surplus is actually available, rather than treating Drop telemetry as success proof.
3. A=1 release to A=0, then immediate acquire without supplying an external token. Require IdleImplicit grant, retained entitlement, no raw release. Exercise initial external caller installation, nested installation, worker startup/idle/termination, and shutdown through the actual Registry. Validate owner capabilities at each site.
4. Inject spurious notifications before grant and after grant; loop predicate forbids false admission and ack is single-use. Exercise counter/slot boundaries with test-sized bounds and telemetry caps. Recorder exhaustion must not alter grants/results. Native bound handling must never wrap or oversubscribe.
5. Controlled query fixture: consumer releases while waiting, another holder takes transferred allowance, producer signals query readiness, but external tokens remain held. Confirm query guard released by obtaining it from producer/controller while reacquire is Pending. Release named allowance, assert linked grant/ack/return then resumed. Repeat normal completion, poison/error diagnostics, and real query-cycle recovery.
6. Test helper errors and raw release errors using a platform-supported real broken jobserver endpoint or a narrowly scoped IO fault seam around the actual Client operations. State-machine tests still use real Proxy. Label injected IO validation separately from real endpoint validation. Check errors are not grants and diagnostics/exit status are preserved. If platform cannot induce it safely, report this gate blocked.
7. Pause Granted before ack during shutdown and verify no premature destruction or fabricated progress. Drain callbacks/race capture seal; assert incomplete inventories when genuinely outstanding. Test explicit future cancellation only if implemented. Two actual pools/Proxies and sibling process sharing Client must reject cross-namespace lineage and leave external supply origins opaque.
8. Run inline/migrated query joins and opaque helping work, capture attachment after startup, and lost-record injection. Only valid active schema4 points bind; administrative/helper events need not have task points. Remove individual rows to verify independent inventories detect omissions.
9. For every deterministic scenario, capture off/on with identical controlled decisions: same assertions, artifacts, diagnostics and exit status, no added Dirty units on unchanged recorded/unrecorded builds. Do not require incidental unconstrained scheduling orders identical; explicitly compare the protected acceptance properties and predetermined gate outcomes.

Suggested implementation order: private Client fixture and owner-site coverage; native ticket protocol capture disabled; barrier matrix; capture adapter/inventory; query linkage; attachment/loss tests; benchmarks; default decision.
