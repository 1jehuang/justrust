# Retrospective re-executed value evidence

This is measurement ladder 2 instrumentation, not a reuse change. The native
`hash_result_and_alloc_node` path has already executed the provider and computed
its normal optional stable result fingerprint. With self-profiling enabled, it
looks up the same stable dep-node key in the previous graph and records one
classification if that key exists. New keys are excluded.

## Marker contract

`GenericActivity` interval labels use a static dep-kind name as their sole
function argument:

| Ordinary execution | Eval-always execution | Meaning |
| --- | --- | --- |
| `jr_incremental_reexecuted_same_value` | `jr_incremental_eval_always_same_value` | Current and previous stable result fingerprints compare equal. |
| `jr_incremental_reexecuted_different_value` | `jr_incremental_eval_always_different_value` | Current and previous stable result fingerprints compare unequal. |
| `jr_incremental_reexecuted_no_hash` | `jr_incremental_eval_always_no_hash` | Current execution has no result-hash function. Value equality is unknown. |

The name is generated by `define_dep_nodes!` without formatting a key or allocating
a formatted query name. All extra previous-graph lookup and classification work
is inside `tcx.prof.enabled()`. Profiling off still computes exactly the existing
optional result hash, then uses the unchanged allocation/coloring path. The
instrumentation does not change graph decisions, stable hashes, serialized cache
formats, cache keys, diagnostics, or exit status.

Proven-green provider recomputation uses `with_ignore` and does not traverse this
path. The existing green-route marker families remain separate and unchanged.
Eval-always providers are inventoried separately because they execute
unconditionally and do not track ordinary query dependencies.

## Interpretation limits

Equal result fingerprints do **not** prove that inputs changed, a provider was
avoidable, an execution was redundant, or future reuse is sound. Result hashes
are the compiler's existing stable hashes, not a new semantic equality oracle.
No-hash events do not establish equal or different values. These counts describe
records, not distinct keys or the number of providers that could safely be
skipped. Markers absent from a capture remain unknown, not measured zero work.

The intervals cover marker recording after provider execution. They do not
measure provider elapsed time, CPU work, critical path, or savings. No elapsed
bound, speedup, reuse default, or performance promotion follows from this work.
No hosted or comprehensive benchmark is part of this acceptance gate.

## Direct native acceptance

Run against a frozen compiler with its matching freshly built standard library:

```sh
python3 bench/reuse-reexecuted-accept.py \
  --rustc /path/to/frozen/sysroot/bin/rustc \
  --output /existing/private/parent/new-capture
python3 -m unittest discover -s bench -p test_reuse_reexecuted_accept.py -v
```

The harness runs profile-off and profile-on with independent persistent
incremental directories, both with `-Zincremental-verify-ich`. Profile-on uses
`-Zself-profile-events=generic-activity,function-args`, explicitly recorded in
the report. This includes the required marker family but not query-provider
intervals. In a failed compilation, unfinished query-provider intervals can
retain the native `EventId::INVALID` sentinel and the existing strict whole-profile
decoder rejects them. Selecting only generic activities avoids those unrelated
records without relaxing decoder integrity checks. Ordered cases are
initial, unchanged, actual body edit, type error, and recovery. It compares exact
compiler status and diagnostics, normalizing only each source directory, and
compares successful program status/stdout/stderr against each other and the
expected output. A type error must return ordinary compiler status 1. Profiles
must contain valid generic intervals with a resolved static dep-kind argument.
An initial fresh incremental directory must not contain prior-node markers.
The fixture must observe both ordinary same-value and different-value records
across the subsequent captures. Unobserved families remain unknown.

`acceptance.json` retains source text, commands, complete diagnostics, output,
compiler `-vV`, compiler SHA-256, sysroot query, exact rustc_driver paths and
SHA-256, successful binary hashes, native profile paths/hashes, and per-kind
marker counts. Partial or failed reports are retained. Existing output
directories are never overwritten. Raw profiles stay in the private capture
directory. The offline decoder separately inventories the same optional native
labels without changing its existing green-route contract.
