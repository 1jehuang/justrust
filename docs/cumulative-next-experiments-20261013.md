# Next hosted optimization experiments after the reserved scaling window

This is an experiment plan, not a new speed claim. Current verified opt-in reference is5.32 to4.56 seconds on24-core M8azn; body/no-op are within noise. 10x stock-local is unmet. The next96-core host epoch cannot be compared causally with those24-core results without a fresh matched control.

1. Coordinate both the own-host lease and laptop compiler quiet window. The previous host-exclusive benchmark still had local stock contention. Record actual host CPU/type, installed client hash, selected rustc/Cargo, profile flags, source pins and cache state. No hosted request while another agent owns the window.
2. Recover the existing public round-robin stock-local/hosted baseline, rotating order, two warmups and at least seven measured samples. Use `--quiet-wait 30`, but reject every remaining noisy comparison rather than treating a timeout as quiet. The new stock-report guard makes this rejection visible automatically. Preserve raw data.
3. Review the owner's actual `bench/scaling.sh` results before changing concurrency. The earlier6-versus8 and8-versus16 thread trials were flat. More cores are a hypothesis for cold parallel units, not proof of a faster single large UI crate. Run same-host before/after controls, not hardware-epoch arithmetic.
4. Keep candidate compiler and portable native Cargo experiments separate. The completed comparison used byte-identical official Cargo; a native fork/bootstrap adds another variable. Disable the Cargo daemon/test-pool for the compiler-only control, then test their individual contribution on the same source/host/client epoch. Honor normal billing admission for every actual build.
5. Only investigate a new test-filter timing experiment if the new scaling/profile data gives a concrete reason. Earlier filter-only warm speed was within noise. The real3-test compiled harness and full1313-test cache restoration are now verified, but those correctness observations are not an optimization speed claim. Keep filtering opt-in.
6. Reject deferred charge bookkeeping: `recordQueued` inserts the queued run and touches host activity before admission returns. Its visibility gates and active-host reclaim protection are tested. Moving that work after success could let a new run be reclaimed; do not trade safety for the observed roughly67ms lookup path. No production change was made during this investigation.
7. A compiler mono/partition-cache implementation remains blocked by the fork's soundness/reviewer gates. No such patch, test-planning substitute or savings claim is part of this plan. Concentrate on justrust-owned safe scheduling, transport, cache and report improvements justified by measurements.
8. Before shipping a behavioral improvement, repeat actual hosted check/full justrust tests/strict lint and real pinned edited Desktop tests, preserve complete errors, verify artifact reuse and caller permissions, and publish exact owned run exports with before/after suite comparison. Full-UI baseline failure parity is not a clean promotion gate. Preserve peer changes, reinstall changed client behavior and commit/push each validated improvement.
