## Exact artifacts and the mixed-output normalization boundary

Full public stdout is stored outside the source captures, in the private local
artifact directory `dispatch-provenance-analyzer-20261015-mFGsR7`. Directory mode
is 0700 and each graph file is an exclusive, non-overwriting 0600 artifact. Every
compact report records its own exact graph artifact basename, byte length and
SHA-256. Full relation rows are not committed here.

The four non-timing graph stdout artifacts are byte-for-byte identical to the
existing accepted public stdout artifacts. **The mixed timing stdout is not
byte-identical**, and its first exact-byte comparison failure was retained in the
local task log. Neutral snapshot routing reverses the outer query/pool assessment

the first assessment, so its placement changes from the pool object to the query
object. A bounded follow-up comparison verified:

- The resource aggregate occurs exactly once in each output and its entire value
  is identical.
- After removing only that known aggregate placement, complete assessment objects
  match exactly when keyed by `(producer, capture_id)`. No provenance relation,
  CPU assessment, clock assessment, or other field is excluded.
- The analyzer does not promote the aggregate into its compact reports.

## Timing and coverage boundaries

Untimed captures retain an explicitly unaligned public clock assessment. They do
not acquire inferred CPU measurements. The mixed capture has a validated aligned
query clock and 379 measured exclusive CPU segments across three observed
threads: 307,349,245 ns retained observed CPU, partitioned into 91,957,667 ns task
CPU and 215,391,578 ns opaque CPU. These values exactly match the accepted public
pool assessment, with no segment loss, active segments, failed segments or clock
failures reported. The pool-only `query_clock_aligned` field remains false, as
specified by that assessment's narrower authority.

These are scoped retained measurements, not total frontend/compiler CPU. All five
reports keep full CPU work, execution span and theoretical parallelism null, and
full-pipeline completeness false. No branch-specific route, critical-path,
parallelism-ceiling, performance nonregression or speedup claim is made.

The 53 focused analyzer tests pass, including the original 40 controls. Schema4
and schema5 default-byte goldens remain unchanged. The five sequential replays
took 31.04 seconds including source-hash checks, with approximately 30.258 child
CPU seconds. The largest reported child maximum RSS was 2,056,828 KiB, a
per-process maximum rather than a simultaneous aggregate memory measurement.
